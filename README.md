# دستیار خرید حضوری ترب — MVP محلی

رابط فارسی RTL با FastAPI، جست‌وجوی قطعی روی CSV و دموی صوتی مرورگری از کارت پیشنهاد فروش. تماس تلفنی واقعی وجود ندارد. پوشه در ابتدا فقط `spec.md` داشت؛ دیتاست بعداً توسط کاربر اضافه شد. هیچ کد یا Git قبلی وجود نداشت. فایل‌های خام دست‌نخورده مانده‌اند.

## اجرا

Python 3.12 و مرورگر Chrome/Edge جدید. Node فقط برای بررسی نحو JavaScript استفاده شده؛ اجرای برنامه به آن نیاز ندارد.

```powershell
cd D:\torob_assistant
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
# .env محلی ایجاد شده است؛ کلید را فقط همان‌جا وارد کنید.
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

باز کنید: http://127.0.0.1:8000 ؛ OpenAPI: `/docs`. بارگذاری اولیهٔ CSV روی این دستگاه حدود ۳۰–۳۵ ثانیه طول کشید. برای توسعهٔ این دادهٔ حجیم از `--reload` استفاده نکنید؛ هر بار ایندکس حافظه‌ای بازسازی می‌شود. یک worker اجرا کنید؛ حافظه و جلسه‌ها بین workerها مشترک نیستند.

## دادهٔ واقعی و محدودیت‌ها

دادهٔ UTF-8 کاربر: `dataset/shops.csv` دارای ۶٬۴۷۶ سطر؛ `products.csv` دارای ۲۲۵٬۹۰۳ سطر؛ `offers.csv` دارای ۳۳۱٬۵۰۶ سطر. آرایه‌ها/اشیا JSON توکار و مقدار غایب `null` است.

- پوشش پذیرفته‌شده: **۲۲۵٬۸۰۳ محصول، ۳۳۱٬۴۰۱ پیشنهاد، ۶٬۴۷۶ فروشگاه و ۳٬۴۲۸ دسته**. ۱۰۰ محصول با هویت/عنوان/دستهٔ نامعتبر کنار گذاشته شده‌اند؛ ۱۰۵ پیشنهاد ارتباط معتبر نداشتند؛ قیمت ۱۳ پیشنهاد نامعتبر و نامشخص شده است.
- محصولات: `product_id`, `persian_title`, `category_name`, `brand_name`, `model`, `specs`. حداکثر ۲۰ ویژگی کوتاه allowlistشده؛ مقدارهای متعارض یک کلید حذف می‌شوند. تصاویر واقعی دانلود نمی‌شوند؛ جای‌نگهدار خنثی داریم.
- فروشگاه: فقط `shop_id` و `name` و منبع استفاده می‌شود. آدرس، تماس و موقعیت در این MVP استفاده نمی‌شود؛ پیشنهاد محدودهٔ خرید نداریم.
- پیشنهاد: `offer_id`, `product_id`, `shop_id`, `price_toman`, `last_price_changed_at`. `id` کارت، شناسهٔ **پیشنهاد فروش** است؛ `product_id` شناسهٔ واقعی محصول است. درخواست تماس هر دو را منتقل و سرور association را دوباره بررسی می‌کند. مقایسه و بازخورد به `id` کارت/پیشنهاد ارجاع می‌دهند.
- تاریخ قیمت، زمان **تغییر قیمت** است، نه تأیید موجودی یا آخرین مشاهدهٔ فروشنده. قیمت با تاریخ غایب/آینده/بیش از `DATA_STALE_DAYS` روز در فیلتر و مقایسه نامشخص است؛ مقدار خام تاریخی با برچسب جدا قابل نمایش است. حتی قیمت دارای تاریخ، تضمین قیمت امروز نیست.
- موجودی، نقد کاربران و تأیید اقساط کالا در این داده وجود ندارد. payment_options فروشگاه به‌تنهایی اقساط کالای انتخاب‌شده را ثابت نمی‌کند؛ همهٔ این وضعیت‌ها نامشخص‌اند. فیلتر «فقط اقساط/موجود» نتیجهٔ خالی صادقانه می‌دهد.
- دسته‌ها از داده مشتق می‌شوند؛ پوشاک فقط اگر در داده وجود داشته باشد جست‌وجو می‌شود. درخواست دستهٔ غایب نتیجهٔ ساختگی نمی‌سازد. پیشنهادهای اولیه از دسته‌های واقعی هستند.
- برای دادهٔ کوچک، `DATASET_PATH` می‌تواند مسیر JSON با `stores` و `products` باشد. مدل‌ها در `app/models.py` مرجع قرارداد هستند؛ `source` اجباری است و دادهٔ نمایشی باید `demo:true` داشته باشد. JSON خالی `data/catalog.json` فقط fallback توسعه/تست است، نه دیتاست نمایشی محصول.
- به‌روزرسانی: CSV جدید را جداگانه تأمین کنید، مسیر را تنظیم و سرور را راه‌اندازی مجدد کنید. برنامه فایل خام را تغییر نمی‌دهد. بازتولید گزارش: `python -m docs.audit_data` با پایتون محیط مجازی.
- فایل‌های حجیم `dataset/*.csv` در Git ثبت نمی‌شوند و باید جداگانه در همان مسیر قرار گیرند. راهنمای دیتاست و گزارش SHA256 در مخزن ثبت می‌شوند؛ `.env`، محیط مجازی و فایل‌های موقت نیز خارج از مخزن هستند.

## جست‌وجو، قیمت و مقایسه

یکسان‌سازی ی/ک عربی، رقم فارسی/عربی/لاتین، علائم، فاصله و نیم‌فاصله؛ متن اصلی برای نمایش حفظ می‌شود. همهٔ واژه‌های جست‌وجو و همهٔ محدودیت‌ها اجباری‌اند. چند عبارت ساده مانند «نشان بده» حذف می‌شوند؛ این parser عمومی زبان طبیعی نیست. محدودیت قیمتی در متن به درخواست استفاده از فیلتر ساختاریافته منجر می‌شود؛ واحد مبهم حدس زده نمی‌شود.

امتیاز ثابت: نام کامل ۱۰۰ + زیررشتهٔ نام ۴۰ + دستهٔ کامل ۲۰ + هر واژهٔ مطابق نام ۵ + هر ویژگی اجباری ۱۰. تساوی با شناسهٔ ثابت پیشنهاد شکسته می‌شود. SQL فقط پارامتری است. تطبیق ویژگی CSV با کلید/مقدار اصلی دقیق انجام می‌شود؛ JSON کوچک نرمال‌سازی‌شده است. هیچ واحدی تبدیل نمی‌شود؛ ریال با تومان برای فیلتر یا برتری قیمت مخلوط نمی‌شود. ویژگی‌های مقایسه همان کلید و مقدار اصلی‌اند، بدون استنتاج برتری از واحد ناسازگار. «خیر» و «نامشخص» جدا هستند. پیشنهادهای برند در UI به ۱۰۰ برند پرتکرار محدودند.

## API و حفاظت نوشتن

ابتدا `GET /api/config` را با نگهداری کوکی بگیرید؛ مقدار `csrf_token` را برای POST/DELETE در هدر `X-App-Token` ارسال کنید. Origin باید در `APP_ORIGINS` باشد. CORS باز نشده است. کوکی HttpOnly و SameSite=Strict است؛ در HTTPS مقدار `COOKIE_SECURE=true` لازم است. شناسهٔ جلسهٔ دیگر قابل خواندن نیست. این کنترل جایگزین حساب کاربری و سامانهٔ مجوز سازمانی نیست؛ برای اجرای عمومی، رمز جداگانهٔ دمو اجباری است.

| مسیر | ورودی/رفتار |
|---|---|
| `GET /health` | سلامت و تعدادها |
| `GET /api/catalog/filters` | پوشش و فیلترهای مشتق‌شده |
| `POST /api/chat` | `{query,category,max_price,currency,installments_only,in_stock_only,attributes,limit}` |
| `POST /api/compare` | `{ids:[offer_id,offer_id]}`؛ ۲ تا ۴ پیشنهاد متمایز |
| `POST /api/feedback/visit` | `{product_id:<card id>,consent:true,text,purchased:false}` |
| `POST /api/feedback/purchase` | همان، با `purchased:true` اجباری |
| `DELETE /api/feedback/{id}` | حذف متعلق به همان مرورگر؛ اصلاح با حذف و ثبت مجدد |
| `POST /api/calls` | قرارداد spec به‌اضافهٔ `offer_id` برای CSV؛ نام‌ها/ویژگی‌ها با مرجع تطبیق داده می‌شود |
| `WS /ws/calls/{id}` | همان کوکی و Origin؛ PCM/ack/end، نه کلید سرویس |
| `POST /api/calls/{id}/end` | پایان دستی idempotent |
| `GET /api/calls/{id}/result` | پیش از نهایی‌سازی HTTP 409 |

حد HTTP برابر ۶۴ KiB، محدودیت متن/مبلغ/تعداد و رد فیلد اضافی فعال است. حداکثر سه جلسهٔ نهایی‌نشده در برنامه و یک جلسه برای هر مرورگر. رمز `CALL_DEMO_ACCESS_TOKEN` برای ایجاد تماس در استقرار عمومی در هدر `X-Call-Access` دریافت می‌شود؛ این رمز با API key فرق دارد و در UI فقط ورودی رمز است.

ذخیره‌سازی **فقط توسعه‌ای و حافظه‌ای** است: ایندکس کاتالوگ SQLite `:memory:`، بازخورد/متن/نتیجه در حافظهٔ فرایند. پاک‌سازی بازخورد و جلسهٔ پایان‌یافته پس از یک ساعت با sweep هر ۳۰ ثانیه و هنگام دسترسی؛ restart همه را پاک می‌کند. بازخورد به کاربر دیگری نمایش داده نمی‌شود و امتیاز تجمیعی ساخته نمی‌شود. انتخاب DB پایدار، نگهداری تولید و هویت کاربران هنوز باز است. صوت مرورگر یا backend روی فایل/DB/log/telemetry ذخیره نمی‌شود؛ سیاست نگهداری داخلی سرویس‌دهنده باید جداگانه تأیید شود.

## تماس و تنظیمات لازم

مسیر زنده: میکروفون مرورگر → FastAPI WebSocket → **Gisoo integrated Realtime** → پخش مرورگر. پس از پایان و تأیید متن کامل: **متن دوطرفه → BoxAPI → نتیجهٔ معتبر**. BoxAPI صوت دریافت نمی‌کند و در مکالمهٔ زنده نقشی ندارد. `whisper-1` فقط مقدار transcription داخل session گیسو طبق نمونهٔ پشتیبانی است؛ درخواست STT جداگانه ارسال نمی‌شود. این تغییر مطابق اصلاحیهٔ کاربر در `spec.md` است.

`.env` محلی بدون کلید ساخته شده است. فقط نام متغیرها/مقادیر غیرمحرمانه در `.env.example` مستندند:

| متغیر | وضعیت |
|---|---|
| `GISOO_API_KEY` | **شما باید مقدار دهید**؛ هرگز در چت، UI یا مخزن قرار نگیرد |
| `GISOO_REALTIME_MODEL` | در `.env` بر اساس خواستهٔ کاربر `qwen3.8-omni-flash-realtime` انتخاب شده؛ پیش‌فرض کد ندارد |
| `GISOO_TRANSCRIPTION_CONFIG` | نمونهٔ پشتیبانی: `{"input_audio_transcription":{"model":"whisper-1"}}` |
| `GISOO_PROTOCOL_VERIFIED` | فعلاً false؛ بعد از بررسی سازگاری مدل و پذیرش ریسک آزمون دستی true شود؛ به معنی اثبات کیفیت زنده نیست |
| `CALL_EXTRACTION_MODE` | به تصمیم کاربر `boxapi_post_call` تنظیم شده؛ روش دیگر = unconfigured |
| `BOXAPI_API_KEY` | **شما باید مقدار دهید**؛ فقط backend، مستقل از کلید و اعتبار گیسو |
| `BOXAPI_MODEL` | با تفویض انتخاب از فهرست کاربر، در `.env` برابر `gpt-6-luna`؛ کد پیش‌فرض ندارد |
| `BOXAPI_REASONING_EFFORT` | `none` برای استخراج کوتاه؛ سازگاری BoxAPI هنوز زنده تست نشده |
| `CALL_TIMEOUT_SECONDS` | پیش‌فرض ۱۲۰ ثانیه، سقف سخت ۱۲۰؛ session-ready حداکثر ۱۵ ثانیه |
| `CALL_DEMO_ACCESS_TOKEN` | برای میزبان عمومی اجباری؛ رمز اختصاصی دعوت‌شدگان، متفاوت از کلید گیسو |
| `DATASET_PATH`, `DATA_STALE_DAYS` | `dataset` و ۳۰ روز |
| `APP_ORIGINS`, `COOKIE_SECURE` | مبدأ دقیق محلی/HTTPS، بدون wildcard |

دو مدل در [راهنمای رسمی Realtime گیسو](https://gisoo.pro/docs/realtime) فهرست شده‌اند. انتخاب Qwen به‌عنوان گزینهٔ ارزان‌تر، **استنتاج از تعرفهٔ پایهٔ سازندگان** است: [Qwen](https://help.aliyun.com/en/model-studio/qwen3-8-omni-flash-realtime) و [Gemini](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing). قیمت تمام‌شدهٔ گیسو، نرخ تبدیل تومان، موجودی حساب و هزینهٔ Whisper هنوز تأیید نشده‌اند؛ هزینهٔ دقیقه‌ای یا موجودی ساختگی نداریم. [صورتحساب گیسو](https://gisoo.pro/docs/billing) مرجع بررسی حساب است.

PCM16 little-endian mono 24 kHz با `codec=pcm24`؛ VAD سرور، تولید پاسخ دستی بعد از رونویسی فروشنده، شروع دستیار پس از session.updated. مرورگر capture را در حافظه به PCM تبدیل می‌کند و صف پخش حداکثر ۱۰ ثانیه است. بعد از قطع، صف/نسل صوت پاک و پاسخ cancel می‌شود؛ ack قدیمی پذیرفته نمی‌شود. agent text فقط وقتی تمام قطعاتش پخش و ack شده باشند، دقیق محسوب می‌شود؛ متن پاسخ نیمه‌شنیده در نتیجه null می‌ماند. ترتیب نهایی بر پیوند previous_item_id است، نه ترتیب رسیدن transcript. پیوند/متن/ack غایب ⇒ incomplete. مهلت نهایی‌سازی ۱٫۵ ثانیه است؛ تأخیر بیشتر ⇒ ناقص، نه بازسازی ساختگی.

**محدودیت سخت Qwen:** مستندات گیسو می‌گویند truncate فقط ack می‌شود و حافظهٔ پاسخ قطع‌شده کامل می‌ماند. برنامه پس از barge-in پاسخ قطع‌شده را پخش نمی‌کند و به‌جای ادامه با تاریخچهٔ ناسازگار، جلسه را با `error / qwen_context_truncation_unsupported` و نتیجهٔ ناقص پایان می‌دهد. ادامهٔ صحیح مکالمه پس از وقفه هنوز پذیرفته نشده است. تغییر مدل/معماری خودکار انجام نشده. سازگاری VAD دستی، voice، خروجی transcript و پیوند آیتم‌ها برای هر مدل نیاز به smoke test دارد؛ Gemini هم recovery کامل truncate در این نسخه ندارد.

سقف backend: یک پاسخ آغازین + حداکثر دو پاسخ تکمیلی؛ دستور مدل هر بار فقط یک سؤال تکمیلی را مجاز می‌کند. سؤال‌های علامت‌گذاری‌شدهٔ بیش از سقف در transcript خطا محسوب می‌شوند؛ کنترل کامل معنایی تعداد سؤال‌های واقعاً گفته‌شده بدون آزمون زنده اثبات نشده است. شمارندهٔ نتیجه تعداد نوبت‌های تکمیلی مصرف‌شده است و UI همین را می‌گوید.

استخراج اصلی فقط BoxAPI است؛ Function Calling فعلاً لازم نیست. طبق [مستندات BoxAPI](https://boxapi.ir/docs/ai/)، endpoint ثابت `https://ai.boxapi.ir/ai/v1/chat/completions` است. فقط متن کامل، پس از پایان عادی و تأیید پخش/ترتیب، ارسال می‌شود. JSON Schema درخواست و Pydantic پاسخ را محدود می‌کنند. شناسه‌ها، دلیل پایان و transcript از مدل گرفته نمی‌شوند. شواهد باید نقل‌قول دقیق فروشنده باشند؛ اصلاح بعدی قیمت/موجودی مقدم است. قواعد محلی صرفاً شاهد را اعتبارسنجی می‌کنند و هیچ حقیقتی به‌عنوان استخراج اصلی تأمین نمی‌کنند. خروجی بد/مبهم یا شاهد نامعتبر ⇒ unknown/null و extraction_status=invalid؛ هیچ fallback مدل یا درخواست تکراری خودکار نداریم. raw_text متن واقعی فروشنده را حفظ می‌کند.

انتخاب `gpt-6-luna` برای کار متمرکز استخراج کوتاه بر اساس [مستندات رسمی OpenAI](https://developers.openai.com/api/docs/models/gpt-6-luna) و اجازهٔ کاربر انجام شده؛ تعرفهٔ BoxAPI و دقت فارسی این مدل در این پروژه زنده اندازه‌گیری نشده‌اند. درخواست فقط یک بار در هر جلسه، با سقف ۱۲۰۰ توکن completion و timeout بیست ثانیه انجام می‌شود. usage و cost گزارش‌شده در extraction_usage حافظه‌ای ثبت می‌شوند؛ واحد پول هزینهٔ فاقد واحد حدس زده نمی‌شود. حتی پاسخ JSON نامعتبر، اگر usage داشته باشد مصرفش ثبت می‌شود. حذف صوت و بی‌نیازی به ذخیرهٔ پایدار همچنان برقرار است.

## تست و دمو

```powershell
.\.venv\Scripts\python -m pytest -q
node --check static/app.js
node --check static/capture.js
# بررسی مرورگر اختیاری؛ سرور محلی باید در حال اجرا باشد. این تست هزینهٔ گیسو ندارد.
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python tests/browser_check.py
```

تست‌های پیش‌فرض هیچ اتصال زنده‌ای به مدل ندارند. pytest temp فقط در `.pytest_tmp` همین پروژه ساخته می‌شود. نتیجهٔ نهایی تست‌ها در `docs/verification.md` ثبت می‌شود. تست مرورگر از Chrome نصب‌شده استفاده می‌کند؛ عکس‌های `docs/desktop.png` و `docs/mobile.png` خروجی محلی‌اند.

دمو: «لنز سونی» را جست‌وجو کنید؛ دو کارت را مقایسه کنید؛ فیلتر اقساط را بزنید و خالی‌بودن صادقانه را ببینید؛ «نظرات» را بپرسید؛ از کارت استعلام را باز کنید و هشدار عدم تماس واقعی/تنظیمات را ببینید؛ بازخورد بازدید و خریدِ نیازمند تأیید را جدا آزمایش کنید. تماس زنده تا تکمیل تنظیمات unavailable است.

آزمون زنده فقط پس از اجازه: **برای هر مدل دو مکالمهٔ حداکثر ۳۰ ثانیه** با همان محصول؛ اول موجودی + قیمت صریح + اصلاح فروشنده و کنترل دوطرفهٔ متن؛ دوم قیمت بی‌واحد + سؤال تکمیلی + وقفه + پایان دستی. برای استخراج BoxAPI نیز یک متن کامل با اصلاح قیمت و یک متن مبهم؛ ناقص‌بودن متن باید بدون درخواست خارجی تست شود. قبل از هر آزمون، موجودی واقعی و نرخ‌ها را در دو پنل جدا بررسی و سهم حداکثر هزینه را تعیین کنید؛ پس از هر آزمون گزارش مصرف را ثبت کنید. با اولین خرابی رونویسی/متن/پخش/استخراج یا نرسیدن به ready متوقف شوید. سقف کل پروژه ۱٬۰۰۰٬۰۰۰ تومان است؛ اعتبار ۳ دلاری BoxAPI طبق گفتهٔ کاربر فقط برای استخراج است و اعتبار گیسو محسوب نمی‌شود؛ ماندهٔ واقعی هنوز تأیید نشده. برنامه ادعای سقف مالی خودکار ندارد. **هیچ آزمون پولی یا بررسی موجودی انجام نشده است.**

## لیارا — فقط مراحل دستی، استقرار نشده

Dockerfile آماده است؛ build Docker روی این محیط آزمایش نشده. نام برنامه را خودتان انتخاب کنید. با راهنمای رسمی [Liara CLI](https://github.com/liara-cloud/cli/blob/master/README.md)، برنامهٔ Docker بسازید و پورت **8000** را انتخاب کنید؛ کد به `0.0.0.0:8000` گوش می‌دهد. پس از تأیید خودتان فرمان `liara deploy --platform docker --port 8000 --app YOUR_APP` را اجرا کنید؛ این فرمان اینجا اجرا نشده است.

Secrets را در تنظیمات محیط سرویس قرار دهید، نه image. `DATASET_PATH=dataset`، دامنهٔ HTTPS دقیق در APP_ORIGINS، COOKIE_SECURE=true، رمز جداگانهٔ دمو، یک replica/worker و حافظهٔ کافی برای ایندکس لازم‌اند (در مشاهدهٔ محلی فرایند حدود ۳۸۱ MB RAM داشت؛ ظرفیت واقعی میزبان را اندازه بگیرید). با restart دادهٔ بازخورد/جلسه از بین می‌رود. قبل از پذیرش، `/health`، origin/cookie، مسیر WebSocket و میکروفون HTTPS و محدودیت timeout پراکسی را دستی بررسی کنید. فضای دیسک صوت یا DB پایدار اضافه نکنید؛ تصمیم نگهداری تولید هنوز گرفته نشده است.
